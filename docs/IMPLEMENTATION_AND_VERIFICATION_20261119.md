## Seeder commands (Development-only; never production)
From `backend` in Windows PowerShell, with a dedicated disposable development PostgreSQL database and `.env` configured:
```powershell
npm install
npx prisma generate
$env:NCR_DEMO_SEED_CONFIRM = 'YES'
$env:NCR_DEMO_SEED_PASSWORD = 'Set-A-Unique-Long-Demo-Password'
npm run db:seed:ncr-demo
Remove-Item Env:NCR_DEMO_SEED_CONFIRM
Remove-Item Env:NCR_DEMO_SEED_PASSWORD
```
The seeder deliberately refuses NODE_ENV=production, does not truncate/delete/update existing property data, and only creates new records under the synthetic demo owner. A repeat run checks owner/title and property/room label to avoid duplicate demo rows. Because IDs are generated by Prisma, this is idempotent with respect to these keys, not deterministic-id seeding. Any database writes should still first be trialed on a disposable database.

## Deploy and verify
1. Keep an independent copy of your entire working project. Unzip the distribution; inspect `PATCH/manifest.json`.
2. Dry run from PowerShell 5.1 or later:
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\APPLY.ps1 -ProjectRoot 'C:\Users\DELL\OneDrive\Desktop\GoyalNest_v1_1_1' -DryRun
```
3. If the preflight passes, rerun the command without `-DryRun`.
4. Frontend: `cd frontend; npm ci; npm run build; npm run dev`.
5. Backend: `cd backend; npm ci; npx prisma validate; node --test ../tests/*.test.js` and test all flows against local PostgreSQL.
6. SMTP: configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` (check existing `env.js`). Trigger booking create/approve/reject and activation in TEST database; inspect EmailOutbox statuses. Provider acceptance is NOT equivalent to inbox delivery.
7. Payment: test Razorpay TEST signature, cash/cheque owner approval, partial settlement and duplicate webhook replay. Do not test against live funds.
8. Browser: check tenant dashboard gap, edge toggle expanded/collapsed, mobile drawer and notification popup; then all other portal navigation.
